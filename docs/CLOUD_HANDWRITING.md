# Pri Learning cloud handwriting

Pri Learning can optionally use OpenAI vision as the authoritative handwriting transcription path while preserving Pri Ink as the offline fallback.

This feature is **opt-in**. With no cloud endpoint configured, Pri Learning behaves as before and handwriting recognition stays on-device.

## Architecture

```text
Apple Pencil / browser ink strokes
        │
        ├── Pri Ink local/native recognition ───────────────┐
        │                                                   │
        └── tight black-on-white ink raster                 │
                │                                           │
                ▼                                           │
        Pri cloud handwriting gateway                       │
                │                                           │
                ▼                                           │
        OpenAI Responses API                                │
        GPT-5.6 Terra                                       │
                │ low confidence / ambiguity               │
                └──────────────► GPT-5.6 Sol fallback       │
                                                            │
confident cloud result ───────────────► authoritative reading
uncertain/unavailable cloud ──────────► keep local result ──┘
```

The cloud request contains **only a raster rendered from the captured ink vectors**. It does not contain the question, expected answer, student profile, surrounding UI, marks, feedback, or raw Pencil timing/pressure metadata.

The server sends OpenAI requests with `store: false` and Structured Outputs. The transcription prompt explicitly says not to solve or repair the student's mathematics: `2 + 2 = 5` must remain `2 + 2 = 5` if that is what was written.

The OpenAI API key exists only in the gateway process. **Never put `OPENAI_API_KEY` in a `VITE_*` variable, source file, Swift file, commit, or browser storage.**

## Defaults

- Primary model: `gpt-5.6-terra`
- Escalation model: `gpt-5.6-sol`
- Primary acceptance threshold: `0.92` model-reported OCR confidence
- Image detail: `original`
- One request after the existing handwriting quiet window, not after every stroke
- If Terra is uncertain, Sol is asked for a second read
- If the two cloud readings still disagree, cloud is not allowed to silently replace Pri Ink

These confidence numbers are a launch guard, **not a calibrated accuracy claim**. The real-writer corpus must be used to tune the threshold before declaring the cloud path production-ready.

## First local test on Mac + iPad Safari

From the repository root:

```bash
npm run setup
npm run build
npm run serve:lan
```

`serve:lan` prints the HTTPS address for the Mac. Open that address on the iPad and trust the generated local certificate if this is the first run. It also creates `scripts/.lan-cert`, which the cloud gateway reuses automatically.

In a second Terminal window, set the API key **only in your shell** and start the gateway:

```bash
export OPENAI_API_KEY='YOUR_KEY_HERE'
npm run cloud:ink
```

The gateway prints an endpoint similar to:

```text
https://192.168.1.20:4190/v1/handwriting/recognize
```

A Pri Learning page served from localhost or a private-LAN address automatically looks for the gateway on port `4190`, so the Safari LAN test does not need a custom rebuild.

Now write a few multi-line expressions on the iPad. A confident result should show an engine label beginning with:

```text
Cloud handwriting · OpenAI GPT-5.6 Terra
```

or, after escalation:

```text
Cloud handwriting · OpenAI GPT-5.6 Sol
```

If the gateway is stopped, unreachable, unconfigured, or uncertain, the local/native recognisers continue to work.

## Native Swift package test

The bundled native app runs from the custom `prilearning://` scheme, so it cannot infer the Mac gateway address. Build the endpoint into the web bundle explicitly:

```bash
VITE_PRI_CLOUD_INK_ENDPOINT='https://YOUR_MAC_LAN_IP:4190/v1/handwriting/recognize' npm run build
npm run sync:ios
npm run check:ios
```

Then run `ios/PriLearning.swiftpm` in Xcode or Swift Playgrounds. The API key is **not** included in that bundle; only the Pri gateway URL is.

If you are using the local TLS certificate, make sure the iPad has already trusted the certificate generated by `npm run serve:lan`.

## Configuration

Gateway environment variables:

| Variable | Default | Purpose |
|---|---|---|
| `OPENAI_API_KEY` | required | Server-side OpenAI API key |
| `OPENAI_HANDWRITING_PRIMARY_MODEL` | `gpt-5.6-terra` | First OCR model |
| `OPENAI_HANDWRITING_FALLBACK_MODEL` | `gpt-5.6-sol` | Ambiguity fallback |
| `OPENAI_HANDWRITING_MIN_CONFIDENCE` | `0.92` | Escalation/acceptance guard |
| `OPENAI_HANDWRITING_DETAIL` | `original` | Image detail sent to OpenAI |
| `OPENAI_HANDWRITING_TIMEOUT_MS` | `15000` | Per-model server timeout |
| `PRI_CLOUD_PORT` | `4190` | Gateway port |
| `PRI_CLOUD_HOST` | `0.0.0.0` | Gateway bind address |
| `PRI_CLOUD_ALLOWED_ORIGINS` | dev wildcard | Comma-separated production CORS allowlist |
| `PRI_CLOUD_CLIENT_TOKEN` | empty | Optional local-development bearer token |
| `PRI_CLOUD_TLS_KEY` | `scripts/.lan-cert/key.pem` | TLS private-key path |
| `PRI_CLOUD_TLS_CERT` | `scripts/.lan-cert/cert.pem` | TLS certificate path |
| `PRI_CLOUD_HTTP` | off | Set `1` to force plain HTTP |

Client build/runtime variables:

| Variable | Purpose |
|---|---|
| `VITE_PRI_CLOUD_INK_ENDPOINT` | Explicit Pri gateway URL, required for the native bundled app and normal public deployments |
| `VITE_PRI_CLOUD_INK_TOKEN` | Optional development token matching `PRI_CLOUD_CLIENT_TOKEN` |
| `window.__PRI_CLOUD_INK_ENDPOINT__` | Runtime override for controlled hosts/tests |

`VITE_PRI_CLOUD_INK_TOKEN` is not a suitable production secret because Vite variables are shipped to the client. Production access control belongs at the product backend/auth layer.

## Production deployment requirements

Do **not** expose `handwritingGateway.mjs` directly to the public internet as-is. Before public launch, put the handwriting service behind Pri Learning's authenticated production API and add:

1. per-user/device quotas and rate limiting;
2. abuse and request-size controls;
3. TLS at the deployment edge;
4. explicit CORS origins;
5. usage/cost telemetry that contains no handwriting payloads;
6. retry/circuit-breaker policy for upstream failures;
7. a real-writer OCR benchmark and acceptance threshold;
8. privacy copy that clearly states when cloud handwriting is enabled.

The local gateway is intentionally small so the model integration can be tested now without turning the unused legacy Express server into the production backend.

## Verification

The OpenAI contract tests use a mocked `fetch`; CI never needs an API key and never makes a real OpenAI call:

```bash
npm run test:ink:cloud
```

The normal Pri Ink tests remain relevant because local recognition is still the offline/failure path.
